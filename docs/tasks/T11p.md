# T11p Durable consent Implementation Plan

> **For agentic workers:** use `executing-plans` yourself; one Agent/Security writer, no helpers.

**Goal:** implement D-013/R-A6 durable grants and blocks without weakening immediate revocation,
logical response commitment, private-store integrity or crash/restart safety.
**Architecture:** load one private versioned snapshot before authorization is usable; a durable
session fence protects crashes and failed writes. Serialize store mutations outside the shared auth
monitor; generation-checked, short in-memory commits preserve T11's logical authorization boundary.
**Tech Stack:** pinned .NET10/ASP.NET/xUnit and existing dependencies; no dependency additions.
**Spec:** D-013, T10 R-A4/R-A6/R-A12/R-A14, `docs/tasks/T11.md`, T11 closure report and both-master
seam/fence approvals `msg_cdc1641ad54a` / `msg_914323a8249e`.

## Review focus
1. Revoke persistence fails, then process dies, then old healthy grants try to return on restart.
2. Slow/faulting disk operations stall unrelated authorization or commit a stale grant over a block.
3. Symlink/reparse/ownership/ACL replacement between check, open, lock, replace and quarantine.
4. Corrupt/unreadable metadata or malicious baked flags silently become authority or prompt retries.
5. User-reset recovery loses blocks without confirmation, or normal shutdown clears an unsafe fence.

## Task1 — private store and restart fence
**Files:** focused path/security, storage/atomic replacement and session-fence units under Persistence;
corresponding focused tests in existing Agent/Security test structure.
**Produces:** trusted initialized state or explicit unavailable health; never ambiguous empty-on-error.
- [ ] Write behavioral failing tests for normal grant/block reconstruction, missing-new-store versus
  corrupt/unreadable/untrusted store, absolute-XDG/fallback paths and exact serialized origin identity.
- [ ] Implement Windows LOCALAPPDATA/Zilo verified user owner + ACL only user/SYSTEM/Administrators;
  macOS Application Support/Zilo and Linux absolute XDG_STATE_HOME/zilo or ~/.local/state/zilo;
  POSIX0700 directories/0600 files. Do not chmod unrelated parent directories or trust inherited ACLs.
- [ ] Reject foreign ownership and symlink/reparse store paths with race-safe handle/identity checks;
  private temp, serialized writer lock, flush/fsync and atomic replace, preserving version/generation.
- [ ] Before stored grants are usable, durably establish a session-dirty fence. Unwritable fence or
  previous unresolved/unclean fence fails closed for non-baked prompts and minting. A corrupt file is
  not automatically deleted/reset. Separately validated baked policy remains independent authority.
- [ ] Fence clears only on clean completion after every mutation is durable. Grant writes and their
  acknowledgement do NOT clear the active session fence. Test crash at each write/replace/fence step,
  including fence creation before grant use and stale temp/lock/fence cleanup after interruption.
- [ ] Run targeted tests red→green, record actual failure, then commit/push coherent milestone.

- [ ] Add barrier/fault tests proving disk await/flush/lock never holds the auth monitor and unrelated
