# T01 — SP-1a transport spike (FE lane, Claude author, GPT reviewer) ★

**Target:** a throwaway spike that proves or disproves how an HTTPS public web page can reach a local
agent on loopback in Chromium, Firefox and WebKit. Implements a feasibility gate for D-003 (read
`docs/planning/DECISIONS.md` D-003 and D-004, `docs/planning/research-opus.md` §1 and
`docs/planning/research-notes-gpt-browser.md`).

**Change:**
1. `spikes/transport/agent-stub/`: a minimal loopback HTTP server, Node/TS (no framework needed). It
   binds `127.0.0.1:<port>` only and exposes:
   - `GET /zilo/v1/hello`;
   - `GET /zilo/v1/events`, a server-sent event stream of 5 ticks, consumed with fetch streaming;
   - `GET /zilo/v1/blob?size=N`, which returns binary data;
   - `GET /bridge`, the S2 prototype page.

   It enforces an exact `Host` allowlist (`127.0.0.1:<port>`, `localhost:<port>`, `[::1]:<port>`),
   an exact `Origin` allowlist with CORS reflecting only allowed origins, and an `Authorization`
   bearer check on everything except `hello`.
2. `spikes/transport/app/`: a test page served over **HTTPS from a non-loopback origin**. In CI, use a
   local CA for a hostname such as `app.zilo.test` mapped through Chromium/Firefox
   host-resolver-rules (or an equivalent mechanism) to a separate local server. It must **not** be
   served from localhost, because that would hide the mixed-content constraint. The page has buttons
   for:
   - `fetch(..., {targetAddressSpace:'loopback'})`, and the same fetch without the option;
   - SSE over fetch streaming;
   - `navigator.permissions.query` for `loopback-network` and `local-network`, inside try/catch;
   - the S2 popup bridge: `window.open('http://127.0.0.1:<port>/bridge')`, a handshake with nonce and
     exact origin and `event.source` checks, a `MessageChannel`, then a relayed typed op ("hello") and
     a bounded ArrayBuffer transfer;
   - COOP detection: the same page served with `Cross-Origin-Opener-Policy: same-origin` should show
     the failure explicitly.
3. `spikes/transport/tests/`: Playwright projects for chromium, firefox and webkit. Cover each
   scenario plus the permission states each browser exposes (granted via context permissions or
   prefs, denied, prompt where it can be automated). Negative controls: a hostile origin is denied by
   the stub, a bad Host is denied, and an HTTP page is used as a control.
4. `.github/workflows/spike-transport.yml`: runs the Playwright suite on ubuntu-latest, and on
   macos-latest for WebKit. Note in the report what runs where.
5. `docs/spikes/SP-1a.md`: a results matrix with one row per scenario and one column per browser
   (exact version). Each cell is pass, fail or n/a, with evidence (log excerpt or screenshot path).
   Real Safari 26 columns are marked **pending**, together with a step-by-step manual script for the
   owner or a Mac runner. Also give a recommendation on S1 vs S2 with reasons. Note what Playwright
   WebKit cannot prove.
6. `docs/spikes/SP-1a-interim.md`: a short handoff note for T10 (contract) covering transport facts
   only. Write it as soon as Chromium and Firefox results exist.

**Constraints:**
- Spike code is throwaway. No production packages.
- Never put tokens in URLs.
- Never claim real-Safari behaviour from Playwright WebKit.
- Do not modify anything outside the allowed files.
