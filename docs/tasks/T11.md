# T11 Agent skeleton Implementation Plan

> **For agentic workers:** use `executing-plans` to implement task-by-task yourself. Orca already
> dispatches this bounded worker; do not create helpers or duplicate reviewers.

**Goal:** implement the M1 HTTP/auth/discovery skeleton against the jointly approved T10 contract.
**Architecture:** ASP.NET Core on pinned .NET10, loopback only; consume merged T11a Core records/interfaces,
security state separate from HTTP handlers, injected discovery and native-consent seams.
Jobs/pages/export and production drivers remain later tasks; advertise only implemented features.
**Tech Stack:** existing .NET SDK/central locks/xUnit; framework reference for ASP.NET Core.
**Spec:** PLAN §3/§4/§8, EXECUTION T11, D-001/003/004/004a/005/008/011,
`api/openapi.yaml`, `api/CONTRACT.md` (read-only), owner directives including no first-party licence.

## Global constraints
- GPT author high (star); Claude review required. Main dependencies T10, T04b and T11a must be merged.
- Do not infer consent from Origin/CORS, loopback, install allowlisting, dev mode or browser gestures.
- Preserve exact serialized Origin identity; classification-only root-dot normalization follows R-T3.
- No NAPS2 dependency, native scanner execution, new wire endpoint, shared trust/key, token URL/log,
  document logging, first-party LICENSE, production signing or SAC-host unsigned execution.
- Resource values, status codes, headers and ordering come from the approved contract, not guesses.
- Keep single-file responsibility boundaries; no single giant Program.cs or custom HTTP parser.
- Record performance numbers without gates pending T56a calibration. No unmeasured support claims.

## Ownership and file structure
- Core models/`IScanBackend` and `docs/tasks/T11-interface.md` are owned/frozen by merged T11a.
  Consume its exact discovery and acquisition boundary; Core changes require a separately reviewed
  follow-up, not parallel edits while T12 consumes it. Job ownership/state/SSE/storage stay outside drivers.
- Create HTTP composition/handlers under `backend/src/Zilo.Agent/` and state/policy services under
  `backend/src/Zilo.Security/`. Program.cs is the entry point, not the implementation container.
- Tests: `backend/tests/Zilo.Agent.Tests/**`, new `backend/tests/Zilo.Security.Tests/**` if useful.
  Scaffold guards were migrated by T11a and are now read-only. Preserve no-NAPS2 and layer direction.
- May update project references, `backend/Zilo.slnx`, exact backend locks and central test package
  entries only when necessary. Prefer no added NuGet packages; new dependency approval is explicit.
- Workflow ownership: `.github/workflows/ci-backend.yml`, new `.github/workflows/ci-contract.yml`.
  Add pinned Linux-only `api/tools/check.sh` job with api/tool/workflow paths, main/PR/manual trigger,
  concurrency, no duplicate macOS work. Do not edit normative `api/**` or FE/SDK files.
- Packaging seam (both masters confirmed): only
  `packaging/linux/smoke/{deb-smoke,rpm-smoke}.sh`, `packaging/windows/install-smoke.ps1`,
  and scaffold description in `packaging/linux/nfpm.yaml`. Preserve all installer/security checks.
- Evidence/handoff: `docs/validation/logs/T11/**`. Port tuple has one named handoff:
  `docs/validation/logs/T11/ports.md`; message the tuple to the masters/SDK owner immediately.

## Review focus
1. Root-qualified/mapped loopback, invalid/duplicate Host/Origin, credentialed browser CORS.
2. Consent-prompt abuse across rotating origins, denial cooldown, stale consent and bounded state.
3. Renewal/family deadlines and replay, cross-origin/family access, revocation while a call is live.
4. Endpoint/method/OPTIONS guard ordering, body-size errors and deterministic typed problems.
5. Long-running agent replacing a console: packaged smoke cannot hang or keep asserting old text.
