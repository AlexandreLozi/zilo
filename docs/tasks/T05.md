# T05 — UX and visual design spec (FE lane, Claude author, GPT reviewer)

**Target:** the design of every user-facing Zilo surface. Read `docs/context/BRIEF.md` (the owner's
flow), DECISIONS D-003, D-004, D-005 and D-008, PLAN §1 and §6, and `docs/planning/research-opus.md` §1
(permission states) and §5.

**Change:** `docs/design/` (spec in Markdown) plus `design/prototypes/` (static, self-contained HTML
and CSS prototypes, with no build integration). They cover:
1. **Scan dialog:**
   - device list with driver badges (WIA, TWAIN, ICA, SANE, eSCL, Virtual), a refresh, and empty and
     loading states;
   - settings bound to device capabilities: source flatbed/ADF/duplex, DPI, colour mode, paper size;
   - a scan button with progress;
   - live page thumbnails as pages arrive, with rotate, reorder and delete;
   - export as PDF or images;
   - error states.
2. **Detection dialogs (D-008 states):**
   - checking;
   - permission `denied`, with per-browser help (Chrome/Edge "Apps on device", Firefox "Device apps and
     services") and an admin policy hint;
   - `unreachable-or-blocked`: Install dialog with "Start Zilo" and a download for the detected
     OS/arch plus a manual picker, live re-check while open, and wording that never claims "not
     installed";
   - outdated (Update dialog);
   - updating;
   - Safari path: the S2 popup explanation, and the explicit "Safari not yet supported on this
     machine" state.
3. **Tray/menu-bar agent:**
   - consent prompt: "<origin> wants to use your scanners — Allow / Deny", showing the exact origin
     and resistant to spoofing (long or IDN origins);
   - list of allowed sites with revoke;
   - status, quit and open-logs actions.

   Give separate notes for Windows, macOS and Linux conventions.
4. **Design tokens:** colour, type, spacing, radius, elevation and motion, as CSS custom properties
   for light and dark themes, and themable by the host app. Neutral Zilo branding. No Dynamsoft look,
   assets or trademarks.
5. **Copy table:** every detection state and every planned error code (`device-busy`, `feeder-empty`,
   `paper-jam`, `cover-open`, `timeout`, `disconnected`, `permission`, `unauthorized-origin`,
   `token-revoked`, `export-failed`, `limits-exceeded`, `unknown`). Leave a column for codes T10 adds
   later.
6. **Accessibility spec:** focus order, focus trap, ARIA roles and labels, live region for scan
   progress, keyboard shortcuts, contrast targets (WCAG 2.2 AA) and reduced motion.

**Constraints:**
- Spec and static prototypes only. Do not touch `packages/`, `apps/` or any config.
- Prototypes must open directly from the filesystem in a browser.
- No external assets apart from system fonts.

**Allowed files:** `docs/design/**`, `design/prototypes/**`.

**Observable acceptance:**
- Each surface above has a prototype file and a spec section.
- The copy table covers every listed state and code.
- Prototypes pass an axe scan. A small Playwright script under `design/prototypes/check/` is
  acceptable, but do not add it to any workflow.
