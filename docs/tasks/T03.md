# T03 — SP-4a packaging dry runs (BE lane; Claude-authored per OD-2 and the liaison's instruction; GPT reviews on resume)

**Target:** unsigned packaging dry runs of the T04b hello agent (`backend/src/Zilo.Agent`) for every
OS. Implements the SP-4a feasibility gate.

**Read first:**
- DECISIONS D-001, D-002, D-008, D-009, D-010, D-010a, **D-011 (every shipped PE is Authenticode-
  signed)**;
- `docs/planning/OWNER-DIRECTIVES.md`, especially **OD-6 (Smart App Control)** and OD-4;
- `backend/README.md` and `backend/T04b-VALIDATION.md`;
- `docs/validation/T04b.md`, which shows how the pinned SDK was installed task-private.

**Change, in this order:**
1. **Linux first.**
   - Build `.deb` and `.rpm` for linux-x64 from a framework-dependent or self-contained publish.
     Choose and justify: LGPL assemblies must stay separate files, so no single-file bundle (D-002).
   - Use a packaging tool with a permissive licence (for example nfpm, MIT, pinned version with its
     checksum verified, installed task-private) or `dpkg-deb` directly.
   - Include a `systemd --user` unit, an XDG desktop entry with `x-scheme-handler/zilo`, the
     dependencies (`libsane1`/`sane-backends`, `sane-airscan` as recommends), and
     postinst/prerm scripts with no network access.
   - **Install/uninstall smoke in a container:** Ubuntu LTS for `.deb`, Fedora for `.rpm`. Check that
     dependencies resolve, the files land where expected, the unit file validates
     (`systemd-analyze verify`), and purge leaves nothing behind.
   - Use a container runtime only if one works **headless from WSL without starting any GUI app on
     the Windows host**. Do NOT launch Docker Desktop. If none is available, fall back to
     `dpkg --root=<scratch> --force-not-root` style checks and `dpkg-deb -c`/`-I` inspection, record
     the container smoke as **pending (no container runtime)**, and make the CI workflow run it on
     hosted runners.
2. **Test-key signing smoke, on Linux only.**
   - Generate a throwaway test key and cert at runtime and never commit them.
   - Sign the Windows MSI and the agent exe with `osslsigncode` (pinned) and verify the signature on
     Linux.
   - GPG-sign the `.deb`/`.rpm` or the repo metadata with a throwaway key and verify.
   - Document clearly that test signing **cannot** satisfy SAC (D-011).
3. **Windows MSI.**
   - Author it with WiX (a pinned .NET tool), building on Linux if the toolchain supports it.
   - Windows-side builds may invoke **only Microsoft-signed tools** (`dotnet.exe` from the official
     zip). Do **not** run any unsigned binary natively on Windows: no installer run, no agent run, no
     tests (OD-6).
   - The Windows install smoke is **pending (blocked-by-host-SAC)**.
   - Per-user install, autostart via a Run key or scheduled task, the `zilo://` protocol registration
     under HKCU, and a clean uninstall, all described in WiX source.
4. **macOS `.pkg`.**
   - Author the scripts and layout: universal publish, `pkgbuild`/`productbuild` scripts, a
     LaunchAgent plist and `CFBundleURLTypes` for `zilo`.
   - Building requires macOS, so the build is **pending (no macOS host)**. Ship the scripts and a
     workflow job that would run on `macos-latest`.
5. **`.github/workflows/packaging-dryrun.yml`:** jobs for ubuntu (deb/rpm plus container smoke),
   windows (MSI build plus install smoke on the hosted runner, where SAC doesn't apply) and macOS
   (pkg). Check it locally with actionlint or a YAML parse.
6. **`docs/spikes/SP-4a.md`:** what was built, the commands, the tool versions and licences, and the
   verdicts per row:
   - deb build;
   - deb smoke;
   - rpm build;
   - rpm smoke;
   - test-sign verify (Linux);
   - MSI build;
   - MSI install smoke (pending, blocked-by-host-SAC);
   - pkg build (pending);
   - notarization (pending, M6).

   Also list exactly what D-011 production signing will need: certificate type, signing points,
   timestamp URL. Logs go to `docs/validation/logs/T03/`.

**Constraints:**
- Do not modify `backend/**` source, apart from adding packaging metadata properties if strictly
  needed. If you need that, ask first.
- No production keys. No secrets in the repo.
- Headless only.

**Allowed files:** `packaging/**`, `.github/workflows/packaging-dryrun.yml`, `docs/spikes/SP-4a.md`,
`docs/validation/logs/T03/**`.

**Observable acceptance:**
- The `.deb` and `.rpm` build locally.
- Inspection checks pass.
- The container smoke passes or is honestly pending.
- The test-key signature verifies on Linux.
- The MSI builds, or is pending with the reason.
- `SP-4a.md` is complete. No row is written as pass without evidence.
