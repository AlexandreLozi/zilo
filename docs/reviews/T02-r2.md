## F4-r2 · Medium · Upstream LICENSE evidence is text-normalized

- **Where:** `spikes/naps2/.gitattributes:6`. The `LICENSE` pattern has no slash, so it matches at
  any depth.
- **Impact:**
  - The worktree is permanently dirty.
  - A routine `git add -A` or `--renormalize` silently rewrites the hashed upstream evidence, so the
    inventories' `licenseFileSha256` no longer matches the committed bytes. That breaks the evidence
    chain D-010b relies on.
  - The author's autocrlf test copies only three root files, so it cannot see this.
- **Fix direction (verified in scratch):**
  - Anchor the rule as `/LICENSE text eol=lf`, and anchor the other two rules the same way.
  - Evidence then resolves `text: unset`, the staged hash stays `6286ef…`, and the root LICENSE
    keeps `text eol=lf`.
- **Failing tests:**
  - `test_f4_upstream_evidence_is_never_text_normalized` (lists all 10 files).
  - `test_f4_staging_license_evidence_preserves_recorded_hash`.
  - Consider adding `test_review_t02_r2.py` to the `gate-tests` CI step.
