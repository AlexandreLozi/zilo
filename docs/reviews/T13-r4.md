## Findings

1. **P2 — Restart cleanup escapes the run signal and starts a credential write after deadline or dispose.**
   `packages/sdk/src/client.ts:295,310–325`; `packages/sdk/src/auth.ts:253–258`.
   Authorization's full hello calls `observeInstance`, which awaits `dropAllExcept`
   without forwarding the run signal. Its lock acquisition and eventual write have
   neither abort nor closed-client checks. Aborting the outer detection `step()`
   only discards its result; this cleanup keeps running. Thus the validation claim
   that every credential write checks liveness is false, and r3 finding 1 is not
   fully resolved.

   Evidence: the two new deterministic proofs in `packages/sdk/src/review-r4.test.ts`
   first connect, restart the mock agent, then reconnect and hold the credential
   lock when the replacement token's full hello arrives. Authorization queues its
   restart cleanup behind that lock. After either the 2-second cap or `dispose()`,
   connect has settled; releasing the lock nevertheless increases write calls
   from **2 to 3**. Both tests fail only at that assertion. This is a write that
   **starts after** teardown, not an atomic write already in progress.
   Forward cancellation through restart cleanup and guard its critical section
   and write, while retaining the renewal-recovery and instance-loss behavior.
