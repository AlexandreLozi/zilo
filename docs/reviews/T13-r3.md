## Findings

1. **P2 — An authorization already in flight can issue a token after the overall deadline.**
   `packages/sdk/src/detection.ts:375–379`.
   The guards surround `authorize()`, but no run-owned deadline timer aborts its
   signal while it awaits credential storage or transport. The post-await guard
   cannot undo issuance. Proof: `packages/sdk/src/review-r3.test.ts:31–54` connects
   once, holds the credential-store lock during reconnect, advances 2.5 seconds
   against a 2-second cap, then releases the lock. Token issuance becomes **2**,
   expected **1**: the expired credential is replaced after the run deadline.
   This is still r2 finding 1, not an unrelated auth review. Enforce the deadline
   during pending work and before resumed side effects, not just after completion.

2. **P2 — The final clamped poll can authorize exactly at the deadline.**
   `packages/sdk/src/detection.ts:300–303,431–445`.
   `schedulePoll()` clamps the last timer to the deadline, but `stopIfExpired()`
   accepts equality (`Date.now() <= deadline`). That timer therefore sends another
   consent GET, and an immediate grant can authorize instead of stopping. Proof:
   `packages/sdk/src/review-r3.test.ts:56–86` returns pending with a 10-second poll
   interval and a 4-second cap; at exactly 4 seconds the flow is **ready**, expected
   **unreachable-stopped**. Use consistent boundary semantics: at the deadline,
   stop rather than initiating another request.

3. **P2 — An expired cancelled run can overwrite its replacement run's state.**
   `packages/sdk/src/detection.ts:306–313,342–343,375–376`.
   `stopAtDeadline()` checks run identity only before aborting; it changes the
   snapshot even when the run is stale. The true result of an awaited `hasToken()`
   reaches `authorized()` without checking cancellation. Proof:
   `packages/sdk/src/review-r3.test.ts:88–113` leaves A's token read pending,
   replaces A with B at 1 second, then resolves A at 2.5 seconds. B should remain
   **awaiting-consent** until its own 3-second deadline, but A changes it to
   **unreachable-stopped**. Ignore stale/aborted runs before deadline handling
   and require run ownership before changing state.
