### 1. P2 — Root-qualified localhost bypasses the new loopback classification

Refs: CONTRACT.md:154–184; author tests:338–364, 373–399. Residual of r2 #5.
The host rule matches `localhost` or suffix `.localhost`, but URL serialization
retains a terminal DNS root dot: `new URL('https://localhost.').hostname` is
`localhost.`. That reserved localhost spelling is therefore ordinary eligible
HTTPS even with dev off; `app.localhost.` has the same classification omission.
This host also evades the baked-entry rejection, permitting the allowed/token
tier when explicitly baked or consented. This is not an arbitrary DNS-rebinding
claim or proof of an implemented token bypass: there is no agent here.
Linux's local lookup of `localhost.` returned both `::1` and `127.0.0.1`.

**Required:** recognize the optional final DNS root dot for localhost host
classification only (including its subdomains), without stripping it from the
exact origin used for consent, token binding or CORS. Cover dev on/off and baked
origins; retain the `localhost.example.com` non-loopback control.
New `t10-r3-loopback.test.mjs` exercises the author's existing standalone policy
helpers, not a duplicate replacement model or production runtime: one control
passes, two policy assertions fail (`eligible` versus ineligible/dev-eligible).
