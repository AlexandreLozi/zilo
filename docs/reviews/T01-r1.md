## Numbered findings

1. **Medium — the COOP check can consume the popup's user activation.**
   `spikes/transport/app/app.js:192-205` awaits a network `HEAD` before `window.open`.
   With Chromium's real popup blocker restored and that response delayed six seconds, a genuine
   Playwright click produces `{ok:false, steps:[], code:"popup-blocked"}`. The standard launch
   disables popup blocking, so its successful S2 rows cannot catch this problem. A sufficiently slow
   response breaks the click-to-open path independently of pairing or LNA; an unanswered HEAD also
   delays opening indefinitely. Open the window while the gesture is live and perform asynchronous
   diagnostics afterward. Failing proof: `tests/review-s2.spec.ts`, test beginning `S2: opening the
   popup`. This is reproduced in headless Chromium, not asserted as an observed Safari result.

2. **Medium — binary session validation/backpressure is not the mandatory D-003 protocol.**
   `spikes/transport/agent-stub/bridge.js:67-92` checks only numeric request ID and operation name;
   it never validates a request session ID. `spikes/transport/app/app.js:169-180,243-244` neither
   sends nor checks one. Sending `{id:9001, op:"blob", sessionId:"not-the-bound-session",
   args:{size:8}}` on the legitimately established port succeeds with eight binary bytes and the
   current session ID. Failing proof: `tests/review-s2.spec.ts`, test beginning `D-003: a binary
   request`. This is a protocol-invariant failure for an already authorized channel, **not** a
   demonstrated hostile-origin authentication bypass. Separately, `busy` is released immediately
   after `postMessage`, without a consumer acknowledgment: the size cap and one concurrent fetch
   do not bound bytes queued for a slow/non-consuming recipient. The interim note correctly
   acknowledges missing credit backpressure at `docs/spikes/SP-1a-interim.md:139-140`, whereas
   `docs/spikes/SP-1a.md:97-103` overstates the mandatory-property proof. Validate the envelope and
   add negative/slow-consumer evidence, or explicitly leave those safety properties unproven rather
   than describing the D-003 safety gate as met by this spike.

3. **Medium — navigation leaves an unusable bridge reported as bound.**
   `spikes/transport/app/app.js:243-246` watches only `popup.closed`; it has no liveness/reconnect
   mechanism for navigation or reload. After the full successful handshake/hello/blob/SSE flow,
   navigating the popup to `about:blank` leaves it open and the app's `bridgeState` remains `bound`.
   The poll-based regression test times out after 2.5 seconds; inspection shows there is no later
   navigation check either. D-003 explicitly requires detectable navigation failure and a fresh
   handshake on reload/reconnect. Add detection/invalidation and evidence for recovery; closure
   detection alone is not that proof. Failing proof: `tests/review-s2.spec.ts`, test beginning
   `D-003: navigation`.

4. **Medium — the WebKit/real-Safari recipe does not establish public address space.**
   `spikes/transport/playwright.config.ts:27-38,103-111` marks the source public only for Chromium
   and Firefox. WebKit uses a proxy that actually connects to `127.0.0.1`
   (`scripts/resolver-proxy.ts:16-18,24-31`), with no public-address-space override or diagnostic.
   `tests/fetch.spec.ts:12-23` asserts the HTTPS hostname and `isSecureContext`, which do not prove
   address-space classification. Likewise, `docs/spikes/SP-1a.md:131-136` maps the manual Safari
   source directly to loopback via `/etc/hosts`, without an equivalent override. That recipe is
   executable as an HTTPS-hostname/mixed-content experiment, but not as the requested real
   public-to-loopback validation. The Chromium/Firefox methodology control proves why this
   distinction matters. Preserve the useful WebKit mixed-content observation, label its source
   address-space limitation, and provide a genuinely public HTTPS source (or a demonstrated
   equivalent) for Safari's public-to-loopback gate. Do not label the WebKit `env` cell as proving
   public address space on the strength of a non-localhost URL alone.
