## Findings

1. **P1 — disabled fieldsets stall forward keyboard navigation.**
   `packages/ui/src/focus.ts:21–27`, `packages/ui/src/dialog.ts:523–538`.
   Checking only the control's own `.disabled` includes inputs disabled by an ancestor fieldset.
   Tab is prevented, then `.focus()` on that input does nothing; repeated Tab stays on the prior button.
   Evidence: new `apps/catalog/e2e/review-r1.spec.ts:18` fails in Chromium and Firefox.
   Respect effective disabled state (including the first-legend exception); never target a non-focusable stop.

2. **P2 — visible flattened-tree descendants are skipped.**
   `packages/ui/src/focus.ts:13–17,62–65`.
   `checkVisibility()` is false for `display:contents` wrappers, but their children can be visible.
   Pruning that entire subtree makes its buttons unreachable by Tab in the dialog.
   Evidence: new `apps/catalog/e2e/review-r1.spec.ts:4` fails in Chromium and Firefox.
   Separate eligibility of a node from visibility of its descendants when traversing the flattened tree.

3. **P2 — React opens before applying opening-time props.**
   `packages/react/src/create-component.ts:94–101`, `packages/react/src/index.ts:34–42`.
   Defaults enumerate `open` before `initialFocus`, heading, alert and hideClose; assigning `open`
   synchronously opens/focuses the element with stale configuration.
   Evidence: `packages/react/src/review-r1.test.tsx:18` opens with `initialFocus` in the same update
   and focuses First instead of Safe action. Apply configuration before the open transition.

4. **P2 — the initial controlled open loses its mapped event.**
   `packages/react/src/create-component.ts:94–118`.
   The property effect emits `zilo-open` before the subsequent effect installs event listeners.
   Evidence: `packages/react/src/review-r1.test.tsx:8` mounts `open` with `onOpen`, which receives zero calls.
   Attach listeners before operations that can synchronously emit events.

5. **REQUIRED ADDITION — host-modal fixture (new owner requirement, not an author defect).**
   Main `docs/tasks/T15.md:52–64`; missing from `apps/catalog/src/states.ts:8–32`.
   Add a React Radix Dialog host opening `<zilo-dialog>`: nested trap hand-off and return to the host,
   no body pointer-events lock-out, correct portal/z-index stacking, topmost-only Escape and outside-click,
   and zero axe violations in Chromium, Firefox and WebKit. Radix is catalog-dev-only; licence gate stays green.
   Design assessment: native top-layer `showModal()` (`dialog.ts:421–429`) is a viable stacking foundation
   when the Zilo host remains inside Radix content; arbitrary body portals can violate the host focus scope.
   Current focus stack knows only Zilo dialogs (`dialog.ts:138–139,543`), not the host's active trap;
   bubble-phase Escape suppression (`513–519`) cannot protect against host capture-phase dismissal.
   There is no Zilo backdrop/outside-click handler, nor explicit pointer-events policy for inherited host locks.
   Therefore compatibility is not established by the current design: add coordinated dismissal/focus handling
   and real pointer tests, not just an axe-only fixture or a higher z-index.
