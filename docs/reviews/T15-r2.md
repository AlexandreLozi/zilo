## Findings

1. **P2 — Escape still dismisses Zilo when a non-Zilo modal is topmost.**
   `packages/ui/src/dialog.ts:565–579,587–598`; `packages/ui/README.md:81–94`.
   `openStack` identifies only Zilo dialogs, not the actual topmost modal. The window listener
   unconditionally prevents Escape for that Zilo instance; its bubble handler then closes it,
   even when the focused control belongs to a later native `dialog.showModal()` inside it.
   This is inside the documented DOM-containment contract, and needs no host modal at all.
   Evidence: new `apps/catalog/e2e/review-r2.spec.ts:4` opens a native child modal, verifies focus
   inside it, presses Escape and expects only that child to close. It fails in both Chromium
   and Firefox (zero retries): the underlying Zilo loses `open` instead.
   Coordinate actual modal ownership before claiming Escape; retain protection against the
   outer Radix document-capture listener without claiming keys belonging to a newer inner layer.
   The documented nested-Radix limitation is candid, but is not an acceptable general solution
   to topmost-only dismissal for a React-first integration: an inner modal/popover should consume
   Escape before its parent. Even accepting that explicit Radix limitation does not cover the
   demonstrated native-child case, which the contract permits.
