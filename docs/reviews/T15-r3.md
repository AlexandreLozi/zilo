## Findings

1. **P2 — The older-layer snapshot can permanently misclassify a reopened topmost layer.**
   `packages/ui/src/dialog.ts:468,482–484,592–607,615–619`;
   `packages/ui/src/layers.ts:71–83`.
   The snapshot descends into open shadow roots, but invalidation listens only on `document`.
   Native `close` and `toggle` events do not cross a shadow boundary; events dispatched while an
   element is detached cannot reach the document either. Also, popover toggle events coalesce:
   hide/show in the same task can produce only an `open` notification, which this handler ignores.
   Consequently a genuinely reopened, newer native modal/popover remains in `#olderLayers`.
   Zilo prevents its Escape and closes itself instead of leaving the topmost layer alone.
   **Evidence:** new `apps/catalog/e2e/review-r3.spec.ts:4,30,55` covers (a) an older native modal
   in an **open** shadow root, closed completely before reopening; (b) an older modal closed while
   detached, then reinserted/reopened; and (c) an older popover hidden/shown in one task. All three
   fail in Chromium and Firefox with zero retries: the underlying Zilo loses `open`, while the
   newer child remains open. These are actual close/reopen transitions, not the README's documented
   hidden/shown-without-closing exception. Observe lifecycle transitions across the same roots the
   snapshot scans, and handle detached/coalesced transitions rather than assuming a delivered
   document-level closed notification is a complete opening-order history.

2. **P2 — The suggested native-layer host workaround also disables native Escape dismissal.**
   `packages/ui/README.md:131–136`.
   Radix's `onEscapeKeyDown` receives the original native `KeyboardEvent` (installed
   `@radix-ui/react-dismissable-layer` 1.2.1, `dist/index.mjs:91–105`). Calling
   `e.preventDefault()` prevents the host dismissal, but also cancels the browser's default native
   dialog/popover Escape action. Zilo correctly leaves this event alone, so neither layer closes.
   **Evidence:** `apps/catalog/e2e/review-r3.spec.ts:76` reproduces the callback's cancellation on
   that same native keydown in document capture, registered before Radix; it does not modify the
   fixture or library. In both Chromium and Firefox, host and Zilo survive, but the native child
   also remains open instead of dismissing. The test deliberately models the documented operation,
   not a claim that the fixture already installs that callback. Document the need to explicitly
   dismiss the child as well when preventing the key's default, or recommend the host-library layer
   alternative alone. The underlying cross-library capture-order limitation is acceptable as a
   precise, tested host-integration boundary; the proposed native-layer fix is incomplete as written.

  their `55f6300` versions. Existing tests were only extended; no assertion/exclusion was weakened.
  UI has no dependency addition; Radix remains catalog-only.

  `#zilo-layers`. Its callbacks record causes only: no body resets, outside-event cancellation,
  Escape cancellation or stacking workaround. The Escape and outside-click ordering assertions,
  native child Tab/backdrop coverage, and outer Radix capture regression pass locally.
- Additional headless browser probes in both Chromium and Firefox: an unfocused non-modal native
  dialog or manual popover does **not** steal Zilo's Escape; removal of a newer role-dialog restores
  Zilo dismissal; two Zilo dialogs dismiss inner then outer. A role-dialog surviving a settled
  close/reopen of the same Zilo is captured as older on the next open, as intended. The snapshot is
  reset in teardown and freshly assigned at each open; finding 1 is transition invalidation, not
  reuse of the previous Zilo opening's Set.
- The documented native-child-under-Radix limitation is pinned by the existing test and accurately
  described: unclaimed Escape reaches the host's document capture handler. Using inner Radix instead
  avoids it without fixture hacks. Finding 2 concerns the alternative native-layer advice.
