### 1. Temporary guards vs downstream write sets (Medium, master action)
`backend/tests/Zilo.Scaffold.Tests/ScaffoldBoundaryTests.cs` asserts:
- (a) the four libraries define no types;
- (b) no package whose id starts with `NAPS2` appears in the test project's `deps.json`.

The test project references every production project, so its `deps.json` holds the transitive package
graph.

The file says these guards are temporary and must be replaced when T06/T10 land. Two problems follow:
- T06 adds NAPS2 packages to `Zilo.Drivers.Naps2`. Guard (b) then fails by construction. T06's
  allowed write set (`Directory.Packages.props`, locks, `backend/src/Zilo.Drivers.Naps2/*.csproj`,
  `ci-backend.yml`) does not include `backend/tests/**`, so T06 cannot retire the guard without
  breaking file ownership.
- T11/T12 add types to `Zilo.Core`, `Zilo.Drivers.Virtual` and `Zilo.Security`, which trips guard (a).
  Their write sets are not listed.

I confirmed that guard (a) has real failing power by mutation: adding `public interface IScanBackend`
to `Zilo.Core` turns the test red.

**Resolution, outside the author's write set:** the masters add
`backend/tests/Zilo.Scaffold.Tests/**` to T06's write set (and to T11/T12 when theirs are written), or
name an explicit retirement owner. No change to T04b code is required. The guards are reasonable for
the scaffold itself.

### 2. Production lock files are format v1 (Low)
- The five `backend/src/*/packages.lock.json` files are `"version": 1`. Both test locks are
  `"version": 2`.
- In a scratch copy, `dotnet restore backend/Zilo.slnx --force-evaluate` rewrote all five production
  locks to `"version": 2`, with no other content change.
- A plain unlocked restore (the procedure `backend/README.md` documents) and `--locked-mode` both
  accept the current files unchanged.

So there is no functional or integrity impact today: these projects have no packages. The v1 format
suggests the production locks were generated before central management applied to them. They
self-correct on the first real package addition (T06). Optional fix: regenerate them with
`--force-evaluate`.

### 3. No repository `nuget.config` (Low, advisory)
- Restore uses whatever sources the machine or user config provides. Here and on hosted runners that
  is nuget.org only.
- Locked mode validates each package's `contentHash`, so package substitution would fail restore.
  Integrity is covered for the current three test packages.
- When NAPS2 and native payload packages arrive (T06), a `nuget.config` with `<clear/>` plus
  `packageSourceMapping` would remove the dependency on machine config.
- A root `nuget.config` is not in T04b's write set. This is a recommendation for T06/BE lane, not a
  T04b change.

### 4. Root `global.json` scope (Info)
- The probe project in `spikes/naps2/Probe` resolved SDK 10.0.403 from the root `global.json`.
  Production intends this pin.
- EXECUTION already requires T02 to carry its own `spikes/naps2/global.json`, so there is no conflict.
- Recorded so later spikes or tools know they inherit the exact production SDK unless they add their
  own file.

### 5. Action pinning (Info)
- `actions/checkout@v4`, `actions/setup-dotnet@v4` and `actions/upload-artifact@v4` are pinned by tag.
- `permissions: contents: read` and no secrets are used, so exposure is minimal. SHA pinning can come
  with hardening later. Not required for a scaffold.

### 6. Timeout diagnostics (Info)
In the hanging-agent mutation (below), the failure reads `System.Threading.Tasks.TaskCanceledException :
A task was canceled.` after the 10 s bound. The cause is easy to infer from the test name and comment,
so no change is required.
